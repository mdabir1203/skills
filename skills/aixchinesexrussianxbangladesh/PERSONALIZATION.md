# Personalization Guide

This skill ships as-is. There are no placeholders to replace.

This is a behavioral guardrail, not a procedural workflow. The 17 principles apply the same way to every project, every team, every stack. There is no brand voice to set, no default palette, no personal details to fill in.

If you want to adapt the principles to your team or domain:

- **Add a team-specific principle** as a new section in `SKILL.md`. Use the same numbered structure.
- **Add a domain-specific verification workflow** under principle 1 (Business Reality). Format it the same way as the six existing workflows (Money, Production, Automation, AI, Security, Data migration).
- **Tighten the Completion Gate** (principle 14) by adding items specific to your stack (e.g. "no new lint warnings" for a strict codebase, "no console.log left in" for a production system).

For everything else, the skill is ready to use.
